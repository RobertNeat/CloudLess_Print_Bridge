CloudLess Print Bridge

A local, LAN-only bridge system for a Bambu Lab A1 3D printer. Every service talks to the printer, its microSD card, and its cameras over your own network — there is no cloud account, no vendor relay, and no internet dependency required for normal operation.

This wiki documents the dashboard — the single UI an end user opens day to day — plus the setup paths for getting it (and the backends it talks to) running.

Quickstart — desktop launch

The fastest path to a working dashboard on your own machine: install dependencies once, start each service, then open the dashboard in a browser.

1. Install

pnpm install

Requires Node.js compatible with the pinned pnpm@11.17.0 (see packageManager in the root package.json).

2. Start the backends and the dashboard

Run each command from the repo root, in separate terminals:

pnpm dev:mqtt       # mqtt-puppeteer      — printer control/monitoring, :10320
pnpm dev:ftps       # ftps-remote-manager — SD card file management, :10321
pnpm dev:video      # video-service-hub   — cameras, live preview, recording, :10322
pnpm dev:dashboard  # octo-management-dashboard — the UI, :10300

The dashboard's dev server proxies /api/mqtt, /api/ftps and /api/video to the three backend ports (proxy.conf.json). It expects the backends on their default ports (10320 / 10321 / 10322) — running a backend on a custom port breaks the proxy unless you edit that file to match.

3. Configure the printer connection

Copy the root .env.example to .env and fill in your printer's LAN IP, access code, and serial number (from the printer's own network settings screen) before the backends can do anything useful. See Setup options for the full variable list.

4. Open the dashboard

Once all four commands are running, open http://localhost:10300 in a browser. You land on the Management page by default; the top navigation switches between Management, Files, and Video.

CloudLess Print Bridge

Lokalny system mostkujący (tylko w sieci LAN) dla drukarki 3D Bambu Lab A1. Każda usługa komunikuje się z drukarką, jej kartą microSD i kamerami wyłącznie w Twojej własnej sieci — bez konta w chmurze, bez pośrednika producenta i bez wymaganego dostępu do internetu w normalnej pracy.

Ta wiki dokumentuje dashboard — jedyny interfejs, który otwiera użytkownik na co dzień — oraz sposoby jego uruchomienia wraz z usługami backendowymi, z którymi się komunikuje.

Szybki start — uruchomienie na desktopie

Najszybsza droga do działającego dashboardu na własnym komputerze: zainstaluj zależności raz, uruchom każdą usługę, a następnie otwórz dashboard w przeglądarce.

1. Instalacja

pnpm install

Wymaga Node.js zgodnego z przypiętą wersją pnpm@11.17.0 (patrz pole packageManager w głównym package.json).

2. Uruchom backendy i dashboard

Uruchom każdą komendę z katalogu głównego repozytorium, w osobnych terminalach:

pnpm dev:mqtt       # mqtt-puppeteer      — sterowanie/monitoring drukarki, :10320
pnpm dev:ftps       # ftps-remote-manager — zarządzanie plikami na karcie SD, :10321
pnpm dev:video      # video-service-hub   — kamery, podgląd na żywo, nagrywanie, :10322
pnpm dev:dashboard  # octo-management-dashboard — interfejs użytkownika, :10300

Serwer deweloperski dashboardu przekierowuje /api/mqtt, /api/ftps i /api/video na porty trzech backendów (proxy.conf.json). Oczekuje backendów na ich domyślnych portach (10320 / 10321 / 10322) — uruchomienie backendu na innym porcie zepsuje proxy, chyba że zmodyfikujesz ten plik.

3. Skonfiguruj połączenie z drukarką

Skopiuj główny plik .env.example do .env i uzupełnij adres IP drukarki w sieci LAN, kod dostępu oraz numer seryjny (z ekranu ustawień sieciowych drukarki), zanim backendy będą mogły cokolwiek zrobić. Pełną listę zmiennych znajdziesz w sekcji Opcje instalacji.

4. Otwórz dashboard

Gdy wszystkie cztery komendy działają, otwórz http://localhost:10300 w przeglądarce. Domyślnie trafiasz na Panel zarządzania; górna nawigacja przełącza między Zarządzaniem, Plikami i Wideo.
